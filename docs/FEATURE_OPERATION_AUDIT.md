## 2. P1：优先修正（8 项）

### P1-01 保存连接配置会清空当次密码，打断“保存→测试→连接”

- **触发步骤：**未连接时填写地址、用户名、密码和连接名称 → 点保存配置 → 再点测试或连接。
- **源码事实：**保存成功走 `run(..., 'follow')`，随后调用 `props.select(profile.settings)`；父组件的 `select` 会执行 `setPassword('')`。因此有密码的 Redis 在保存后需要重新输入密码。这不是“密码不落盘”本身的必要动作。
- **影响：**功能清单原来推荐的先保存、再测试流程不能保留一次输入的认证信息。当前无密码连接不暴露此问题。
- **建议：**将“刷新保存列表/更新所选资料身份”与“用户主动切换连接并重置认证草稿”分开；保存成功不重新套用当前草稿，不清空当次密码。继续保持密码不落盘。
- **验收：**有密码夹具中填写一次密码，保存或更新后可直接测试并连接；资料文件与导出文档均不含密码。切换资料、连接成功或关闭设置时仍按约定清理密码。
- **证据：**源码路径确认，未在真实资料上执行保存。[ProfileChooser.tsx:72](../src/client/ProfileChooser.tsx#L72)、[ProfileChooser.tsx:104](../src/client/ProfileChooser.tsx#L104)、[ConnectionForm.tsx:86](../src/client/ConnectionForm.tsx#L86)。

### P1-02 关闭连接配置清空密码，却保留旧“测试通过”状态

- **触发步骤：**带密码的草稿测试通过 → 关闭设置 → 重新打开。
- **源码事实：**关闭只清理密码及打开状态，没有清除 `testOutcome`；重新打开仍可显示旧通过图标，而密码已不同。关闭期间的测试/连接请求也不会因普通关闭而取消，迟到回调仍可改变反馈或连接状态。
- **影响：**通过标记不能准确代表当前表单；用户关闭窗口后，尚未结束的动作缺少明确处置。
- **建议：**清理或更换认证草稿时同步使测试结果失效；关闭时清理当前草稿的测试反馈。为进行中的测试/连接给出明确取消行为，不能把关闭已有连接的设置窗口等同于断开已建立连接。
- **验收：**测试通过后关闭/重开不保留失效标记；延迟测试/连接的取消及迟到回调不污染新草稿；已经建立的连接不会因关设置而被误断开。
- **证据：**源码确认，待隔离延迟响应复测。[ConnectionForm.tsx:51](../src/client/ConnectionForm.tsx#L51)、[ConnectionForm.tsx:80](../src/client/ConnectionForm.tsx#L80)、[ConnectionForm.tsx:108](../src/client/ConnectionForm.tsx#L108)。

### P1-03 恢复资料列表与恢复实际连接并行，可覆盖连接表单

- **触发条件：**会话记住了某条资料，Host 已有实际连接；重新挂载面板时，`connectionStatus` 先返回，`listProfiles` 后返回，且保存资料与实际连接参数不同。
- **源码事实：**状态回调先按实际 target 填表；资料加载回调随后无条件调用 `props.select(profile.settings)`，不检查已连接状态。两项挂载读取没有顺序约束。列表尚未返回时，表单还显示默认地址/端口。
- **影响：**已连接窗口可能显示存档参数；真实连接仍是原来的连接，不能据此说已经“读错服务器”。问题在于连接身份与待编辑草稿混在同一组状态里。
- **建议：**已连接区域展示实际 target；资料列表加载只恢复列表与所选身份，不覆盖实际连接展示。未连接草稿的初始化只在明确的资料选择/恢复阶段进行，并避免覆盖用户已经编辑的内容。
- **验收：**在隔离 UI 测试中反序完成两个 RPC，实际连接信息保持一致；资料加载晚到时不清掉用户新输入的密码/地址。
- **证据：**条件路径由源码确认，本轮没有修改真实资料来制造反序。[ConnectionForm.tsx:43](../src/client/ConnectionForm.tsx#L43)、[ConnectionForm.tsx:65](../src/client/ConnectionForm.tsx#L65)、[ProfileChooser.tsx:56](../src/client/ProfileChooser.tsx#L56)、[ProfileChooser.tsx:77](../src/client/ProfileChooser.tsx#L77)。

### P1-04 已连接时把资料管理也一起锁住

- **现象：**当前连接正常时打开配置，名称、分组、保存、更新、删除、刷新列表、导入/导出均被禁用。
- **原因：**父组件传入 `busy || connected`，子组件用它禁用整个资料区域及转移区域。
- **影响：**不能边查看 Redis 边整理资料；忘记保存当前连接时，也必须先断开才能保存。锁定正在使用的服务器/认证编辑有理由，连资料管理一起锁住过于宽泛。
- **建议：**区分“运行中的连接不可直接改参数”和“本地连接资料管理”。保持实际连接不变，允许保存副本、重命名/分组、刷新列表及导出；编辑其他资料使用独立草稿。切换实际服务器仍由明确的断开/连接动作完成。
- **验收：**已有连接保持可用时完成资料管理，Key 读取目标、DB 与连接 generation 均不被资料操作改变。
- **证据：**当前 DSH 禁用态实测 + 源码。[ConnectionForm.tsx:80](../src/client/ConnectionForm.tsx#L80)、[ProfileChooser.tsx:94](../src/client/ProfileChooser.tsx#L94)、[ProfileChooser.tsx:118](../src/client/ProfileChooser.tsx#L118)、[ProfileTransfer.tsx:46](../src/client/ProfileTransfer.tsx#L46)。

### P1-05 客户端快照的地址、名称、最后命令被截断，详情没有补齐

- **实测：**886×764 视口中，快照宽 680px；ID 列固定 185px，剩余六列约 78px。地址与最后命令出现省略号，列名也被截短。
- **源码事实：**共享表格统一 `table-layout:fixed` 和省略号；地址按钮和普通单元格没有完整值 `title`。选条详情仅含 user/flags/qbuf/omem/sub/psub/ssub，没有补回地址、名称及最后命令。
- **影响：**用户最想确认的“哪台客户端、什么连接、执行什么命令”缺少明确完整查看入口。当前表格只有点地址能选详情，点其他列不会选中。
- **建议：**快照使用自身列宽规则，不套用数据集合的 ID 宽度；允许整行选中并显示完整主表字段及原有详情。长字段提供悬停完整值和就地复制入口；窄窗口可横向滚动，不能只留下无法展开的省略号。单行结果不应占出很大的空白表格区。
- **验收：**使用长 IPv6 地址、长名称、长命令名和多行夹具，完整内容可查看；鼠标和键盘均可选条，详情不盖住表格。
- **证据：**当前界面、DOM 尺寸/属性 + 源码。[ClientListView.tsx:11](../src/client/ClientListView.tsx#L11)、[ClientListView.tsx:24](../src/client/ClientListView.tsx#L24)、[CollectionTable.tsx:53](../src/client/CollectionTable.tsx#L53)、[styles.ts:210](../src/client/styles.ts#L210)。

### P1-06 慢日志有已生成但看不到的明细

- **源码事实：**本机日期、参数字节摘要、可用的原始参数数在 `small` 元素中；共享 `.redis-collection-table small { display:none; }` 把它们全部隐藏。
- **影响：**当前只看到 Unix 秒值、耗时、命令与已记录参数数；不能把日期和字节摘要算成完整的可见功能。慢日志也没有选行明细区来补回这些内容。
- **建议：**移除跨所有表格隐藏 `small` 的通用做法，改由具体视图决定内容层级。时间主显示可读日期，原始 Unix 秒按需查看；选中日志再看非敏感参数长度摘要，继续不展示参数正文。
- **验收：**非空、长整数、参数被 Redis 截断等隔离夹具中，日期/时区、原始秒、执行微秒和安全摘要均有明确入口；不能通过样式误露参数正文。
- **证据：**源码和 CSS 确认；当前真实服务器仅实测空结果。[SlowLogView.tsx:20](../src/client/SlowLogView.tsx#L20)、[SlowLogView.tsx:23](../src/client/SlowLogView.tsx#L23)、[styles.ts:215](../src/client/styles.ts#L215)。

### P1-07 自动刷新会打断正在进行的详情查找与折叠操作

- **实测：**Hash 选中一行，在值预览打开查找并填写合成词；默认 5 秒自动刷新一轮后，原行仍选中，但查找栏和输入内容消失。
- **原因：**集合刷新先清空 cache/result；选中行暂时不存在，`BytePreview` 被卸载，其内部查找、JSON 折叠和滚动状态丢失。共享集合流程存在同类路径；本轮只对 Hash 做了实测。
- **建议：**同一 Key、同一查询的刷新不要卸载仍在查看的预览；刷新结果到达后按原始身份协调选行。新首批没有包含原选条时，明确区分“本批未读到”与“已删除”，不追加无界读取来找回它。切换 Key/DB/查询时仍正常清理旧状态。
- **验收：**Hash/List/Set/ZSet/Stream 的查找、选行、折叠及局部滚动经自动刷新不被无故重置；首批外选条、真实删除、类型变化均有准确状态，不显示别的 Key 的旧值。
- **证据：**当前 Hash 实测 + 共享组件路径。[use-collection-scan.ts:45](../src/client/use-collection-scan.ts#L45)、[HashView.tsx:46](../src/client/HashView.tsx#L46)、[HashView.tsx:83](../src/client/HashView.tsx#L83)、[BytePreview.tsx:18](../src/client/BytePreview.tsx#L18)。

### P1-08 小操作图标仍有 27 个自绘，需要统一库和含义

- **核对结果：**4 个导航图标来自 Phosphor 官方双色路径；其余 27 个操作/状态图标仍是 `Icon.tsx` 本地 path。当前不是全部已经替换成开源图标库组件。
- **表现：**导航为双色填充，操作为 20×20 坐标中的自绘描边；默认显示 14px，图标按钮通常 26×26px。连接测试也使用“定位”形状；漏斗承担范围、路径等多种设置入口；慢日志与读取时间复用 history，信息图标又承担插件信息和服务器概览。

- **验收：**操作图标不再保留手写 path 字典；各处同义动作同图标，异义入口可区分；名称、焦点、禁用、忙态、成功/失败仍可辨认。锁继续是只读状态标记，不能变成暗示“可以解锁”的按钮。
- **证据：**源码、许可与当前按钮尺寸。[Icon.tsx:3](../src/client/Icon.tsx#L3)、[NavigationIcon.tsx:3](../src/client/NavigationIcon.tsx#L3)、[styles.ts:18](../src/client/styles.ts#L18)、[THIRD_PARTY_NOTICES.md:6](../THIRD_PARTY_NOTICES.md#L6)。

## 4. 小图标的具体统一方案

### 4.1 先说明现状

用户提到的“Lucy”可对应 **Lucide**。其官方 React 包提供可直接导入的组件，支持尺寸、颜色、笔画设置与按引用裁剪；组件最终也会渲染为内联 SVG。因此需要替换的是本地手绘路径和混乱的语义，不能把“页面里有 SVG”本身当成问题。[Lucide React 官方说明](https://lucide.dev/guide/react)

导航四图标已有 Phosphor 来源和 MIT 许可，不需要把已选定的青紫橘方案重画一遍。[Phosphor 官方源码](https://github.com/phosphor-icons/core)

### 8.2 哪些问题会随删减退出，哪些仍须修

| 原问题 | 精简后的处理 |
|---|---|
| P1-05 客户端完整字段看不到 | 删除客户端快照后退出，不继续补客户端明细和列宽 |
| P1-06 慢日志明细被隐藏 | 删除慢日志后退出，不继续制作日志详情 |
| P2-01/06/07 快照上下文、取消空白、概览可读单位 | 删除三个快照后退出该范围 |
| P2-04 GEO 选行不一致 | GEO 部分退出；基础集合键盘选行仍需处理 |
| P2-05 URI 非零 DB 与恢复衔接 | 去掉 URI/恢复流程后无需补其衔接；手动选择 DB 的正确性继续保留 |
| P1-02 测试反馈生命周期 | 合并独立测试按钮可去掉旧通过标记；正式连接的取消和迟到回调不能一起忽略 |
| P1-01/03/04 连接密码、草稿/实际身份、资料禁用 | 属于核心连接流程，仍须修复；简化恢复有助于缩小状态来源，但不能把问题算作已经解决 |
| P1-07 自动刷新打断查看 | 属于核心查看流程，仍须修复 |
| P1-08 小图标统一 | 核心按钮仍使用，继续按已列的 Lucide 方案处理，只替换最终保留的入口 |
| P2-02/03 资料删除与错误反馈 | 导入相关部分退出；保留的本地保存、编辑、删除仍需清楚反馈 |

因此，精简能够直接去掉两项快照 P1 及若干相关 P2，并减少后续分支；它不会自动修复连接、刷新或图标问题。不能承诺“删掉低频功能就不会再有 bug”。

### 8.3 删除实现的边界与后续顺序

若随后决定实施，应沿实际依赖逐组删除，避免只藏菜单却继续维护全部后台代码：

1. 删除三类诊断的入口、组件、专用 RPC/DTO、reader/parser、文案、样式和专属测试/脚本；共用能力由剩余引用决定是否保留。
2. 删除不保留的专用类型视图及独立读取路径；String/ZSet 及六种基础类型保持可用。RedisJSON 模块查看与普通 JSON 格式化明确分开。
3. 去掉 URI、连接资料文件转移及恢复 DB/Key 的流程，再简化连接表单状态；接着修好保存密码、实际连接信息与取消。
4. 只对保留的界面统一 Lucide 操作图标，修复自动刷新中的详情状态，调整二级入口。
5. 更新当前功能清单与文档，运行受影响类型、回归和隔离界面验收；日常 DSH 仅在实际实现并验证后更新。

两个已核实的共用边界：

- 删除“服务器概览”不能顺手删掉所有 INFO 支持；DB 目录仍使用 `INFO keyspace`，见 [database-reader.ts:24](../src/host/database-reader.ts#L24) 与 [redis-transport.ts:109](../src/host/redis-transport.ts#L109)。
- Hex/Base64 与显式解码是共享显示格式，见 [value-preview.ts:64](../src/client/value-preview.ts#L64)；它们不是独立服务器连接或 RPC。去掉两种解码菜单不意味着删掉原始字节传输、二进制 Key 身份或只读约束。

分页、取消、过期结果隔离、类型校验和只读边界继续保留；减少的是产品功能与操作分支，不是移除读取正确性。这轮没有执行以上删除，也不把候选范围改写成已经完成的新版本。
