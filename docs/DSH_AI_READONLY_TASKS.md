# DSH Redis AI 原生能力只读任务清单

更新日期：2026-11-02。对应[完整实施方案](DSH_AI_READONLY_IMPLEMENTATION_PLAN.md)。

本清单以用户提出的实际问题为交付单元：在明确的当前连接和 DB 中，先让 DSH 能直接发现、读取和解释数据，再按用户需要联动界面。既有 RO01—RO33 编号及历史记录保留；新增 RO34—RO36 补足自然语言直读、候选发现和有界跨 Key 查询。W01—W05 Redis 写入仍暂缓。本文不构成业务数据进入模型或生产操作授权。

## 1 执行规则

- 优先级按用户任务组织：① 明确目标直接读取（RO34 与 RO27 必要子项）→ ② 线索发现与有限范围查询（RO35、RO36）→ ③ 按问题需要的诊断（RO14、RO15、RO18、RO20 等）→ ④ 按需界面联动（RO07—RO13）→ ⑤ 按实际环境和数据类型选择连接扩展、专业类型。序号表示建议，不构成无关任务的强制串行；确需 SSH、Cluster 等才能连接实际环境时，可前移对应连接工作。
- 总览的依赖适用于对应交付内容或子项；只做部分内容时，只依赖其实际需要的前置能力。不得把格式切换、预设、所有诊断、全部连接模式或专业模块当作普通读取的前置条件。
- 状态区分“历史完成”“进行中”“待开始”和“按需待开始”；历史完成只代表记录所述当时构建和覆盖范围，不表示当前修改后的工作区已回归。只有满足各任务约定的验收，才能将完整任务标为完成。
- 截至 2026-11-02，RO11 的未完成工具接入存在两处 TypeScript 类型错误；当前工作区不可视为可交付构建。恢复代码开发时先修复并核验；本次方案调整不修改代码、不把历史测试结果套用到当前工作区。
- 业务数据只有在用户明确连接、目标和发送范围后才可进入 DSH/模型链路；真实模型验收默认使用隔离的合成 Redis 数据。明确当前连接和 DB，未获请求不自动切换环境或跨库；无法消除歧义时列候选或询问，不能猜测。
- 搜索受用户范围和资源预算约束，MATCH 是 Key 字符匹配，不等同语义或值搜索；扫描完成、读取完整、界面已应用分别记录；不得把部分样本说成全库或原子快照。
- 每项实施前阅读涉及文件与固定版本资料；类型检查优先，关键 Redis 命令有官方契约；不引入 any、旧协议兼容或任意命令后门。持续两次以上补丁仍未解决时重新审视方案。
- 每个可验收节点更新 UPDATE_LOG.md 并按用户要求创建本地 Git 提交；不自动推送、发布或覆盖用户现有修改。未完成的任务不能因已投入或已提交基础代码而标完成。
