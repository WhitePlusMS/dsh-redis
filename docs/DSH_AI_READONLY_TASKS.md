## 当前基线

当前代码已有显式 Key、Hash 字段、Set/ZSet 成员读取，名称扫描、有界 Hash 字段精确筛选、诊断报告及部分连接和界面工具。报告保存用户选定的原始诊断采样，不重新读取；名称扫描要求明确 MATCH，文本身份及范围参数会严格校验。源码 `90acc2c` 的开发包通过完整检查及隔离 profile 安装卸载；此后真实模型验收发现回答边界问题，源码 `4175196` 已新增不读取值的元信息工具并安装日常 profile，新构建真实复验进行中，见[本次记录](verification/user-questions-real-model-2026-11-05.md)。历史证据只对应各自构建。

## 1. 直接查询与查找对象

**用户问题**：“`user:123` 的状态是什么？”“订单 1001 的缓存在哪里？”

**状态：部分场景已通过真实模型，完整节点待验收。** 前一构建的六种基础类型已通过独立 Redis 与真实 ToolRuntime 的无选中直接查询；日常 DSH 与用户模型已在本机真实 Redis 验证直接 Hash、精确字段、名称搜索及空页续读。当前构建新增的元信息工具在真实模型中被调用且未返回值，但模型对 TTL 历史仍作相互矛盾的推断；SCAN 快照表述也未完成复验。独立 Redis 的真实 ACL 测试覆盖允许读取以及 HGET、SCAN 被拒绝。其他类型和异常组合的当前构建真实模型验收仍待完成，见[真实验收记录](verification/user-questions-real-model-2026-11-05.md)。

**完成内容**：当前会话连接/DB 明确时，不选中 Key 即可读取已知对象及必要字段、成员和元数据；用户提供线索时，在指定范围搜索并返回候选、查询模式与覆盖范围。无连接、目标不存在、候选不唯一、无权限、截断和预算耗尽分别说明；线索不足时请用户补充，不猜业务含义或自行跨库。

**验收**：真实 DSH 和用户模型读取合成 Key 与字段，测试面板关闭或无选中；覆盖多候选、无匹配、空扫描页续读、取消、目标变化和错误。六种基础类型按实际交付范围核验，部分值不称完整值。

## 2. 在指定范围筛选和汇总

**用户问题**：“在 `order:*` 中查找状态为 failed 的订单。”

**状态：当前构建已通过独立 Redis 多批专项，并由真实模型在本机 Redis 完成空页续读至首个匹配、按要求停止和未完成状态说明；模型错误计算了目标文本字节数。完整扫描、异常组合及回答准确性仍待验收。** 不代表支持任意表达式或完整数据库统计。

**完成内容**：按用户指定的连接、DB、Key 模式和必要字段有界筛选；控制扫描、读取次数、字节、时长与续读，输出检查数、匹配数、跳过/失败数及时间范围。避免把不相关原始值发送给模型；部分扫描和并发变化明确说明。

**验收**：真实模型调用当前构建筛选合成订单并正确解释范围；覆盖多页、缺字段、类型变化、权限失败、取消、超限和并发变化。SCAN 可能重复，完成也不是原子快照。

## 3. 根据证据排查问题

**用户问题**：“这个 Key 为什么查不到？”“有没有慢查询？”“消息组是否积压？”

**状态：元数据和部分界面诊断已有基础；前一构建的六类诊断通过独立 Redis 与 ToolRuntime 采样及报告回读专项。当前构建已在真实 Redis 和模型中调用服务器概况、慢日志及 Key 内存工具，但模型对单次指标作无证据的判断和建议，诊断回答验收未通过；其他场景仍待验收。**

**完成内容**：按问题复用 Key 类型、TTL、长度等信息；按实际需求和权限提供内存、服务器/DB 概况、慢日志、客户端、Stream 消费组及有限比较。区分证据、推测、无权限、不支持、空结果和失败；用户明确要求时可将选定结果保存为本地报告。

**验收**：在隔离数据和真实模型下逐项验证已交付诊断，记录时间与读取范围；大响应、权限和不支持必须明确。报告不含凭据或未经选择的值；不清日志、踢连接、改配置或推进消息消费。

## 4. 按需在界面核对

**用户问题**：“打开刚查到的 Key。”“解释我选中的字段。”“刷新并以 JSON 查看。”

**状态：当前构建已在日常 DSH、用户模型和真实 Redis 中完成一个 Hash 的 Key/字段定位、单次刷新及 Hex 显示，四项回执与面板一致；旧进程中的动作通道问题未复现。此前 String、Hash、Set、ZSet、Stream 浏览器专项及 List 宿主流专项使用合成数据；预设应用也有合成数据贯通专项。当前构建的其他类型、用户竞争、取消、隐藏及断流等真实验收仍待完成。**

**完成内容**：按明确请求打开面板、定位目标或使用当前选择；支持适用的单次刷新、预览格式和 MATCH 预设。界面动作与查询分离，真实接收端确认后才报告成功；用户新操作优先，保留二进制和 Stream 字段身份。

**验收**：真实 DSH 中逐项核对实际界面与模型结果；单次刷新须通过读取身份绑定完成结果与实际渲染，覆盖旧结果仍在、读取未完成、面板隐藏或关闭、多接收端、用户选择变化、取消、失败、超时、回执丢失和目标失效。无有效回执不得声称已应用，不自动开启持续刷新。

**状态：已保存资料的 AI 连接、候选交换、切 DB 和当前会话断开已有实现；资料连接与断开通过隔离 Redis 和工具专项。切 DB 已通过真实 ToolRuntime 与独立 Redis 验证会话隔离、无效 DB 和权限拒绝；真实 DSH/模型验收待完成。**

**完成内容**：按用户明确意图选择已有连接、切换 DB 或断开；未连接或资料存在歧义时清楚提示。凭据只通过本地受控界面处理，不进入模型参数。mTLS、SSH、Sentinel、Cluster 仅在实际环境需要时按[技术调研](RO21_CONNECTION_ARCHITECTURE_PLAN.md)单独实施；实际连接必需的模式可优先完成。

**验收**：真实 DSH 验证唯一目标、同名资料、缺凭据、失败、切换与资源释放；其他会话不受影响。每个声称支持的拓扑单独验证认证、读取、取消、失败和覆盖，未测试模式或组合不标为支持。

## 共同行为

- 单次及连续读取均有预算；绑定会话、连接代次、DB、目标和续读条件。读取期间切换目标、结果过期、取消及权限失败不得伪装成功。
- 真实模型验收使用隔离合成数据；业务数据发给模型前明确连接、目标及范围。不得修改 Redis 值、TTL、Key 或消费状态，也不提供自由命令或脚本。
- 每节点先做类型检查和相关测试，再用当前构建、真实 DSH 与用户模型验收；记录实际工具调用及未覆盖项。按完成节点更新 `UPDATE_LOG.md` 并创建本地 Git 提交，不自动推送。
- 不停止用户现有服务，只结束本任务创建且确认所有权的测试服务。历史证据如[基础读取](verification/readonly-ro06-real-model-2026-10-28.md)和[界面定位](verification/readonly-ro09-protocol11-2026-11-01.md)仅适用于各自记录的构建。
