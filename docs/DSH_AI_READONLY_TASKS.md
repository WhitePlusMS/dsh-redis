# DSH Redis AI 只读工具验收清单

更新日期：2026-11-06。按用户确认的职责边界修订，与[实施方案](DSH_AI_READONLY_IMPLEMENTATION_PLAN.md)和[交付状态](DELIVERY_STATUS.md)配套。本轮已按当前可用版本收尾，本清单用于后续工具维护，不自动恢复改造或测试。

## 验收口径

插件验收只检查：**工具能正常调用，返回真实、准确且有明确范围的信息，并通过 DSH 工具结果通道正确交给模型。** 界面功能另外核对插件自身的显示和动作回执。

- 工具注册、参数 schema、错误处理、会话/连接/DB 隔离、权限与范围约束、分页和预算仍是插件责任。
- 数据值、类型、编码、时间、单位、来源、完整性、错误及续读状态必须与实际执行一致；必要元信息不能丢失或被误标。
- 在真实 DSH 中核对调用参数、原始工具结果及其进入后续模型上下文的链路；仅卡片显示成功不足以证明结果已交给模型，模型文字也不能代替原始结果核对。
- 模型收到正确结果后如何解释、复述、推断、组织语言或选择后续问题，不作为插件通过/失败条件。模型自由回答错误、遗漏说明或输出 think 不单独记为插件缺陷。
- 若问题来自插件错误数据、缺失必要信息、工具说明/schema 错误、结果传递失败或执行越权，仍修插件；调用尚未到达插件的模型/宿主故障另行定位。模型是否遵循说明不替代 Host 强制约束。
- 已实现、专项通过、真实链路通过分别记录；未测场景保留为覆盖限制，不能因调整责任边界改写为已通过。历史记录中的“完整回答未通过”不再是当前插件交付门槛。

## 1. 直接查询与查找对象

**工具要求**：已知 Key 可直接读取，不要求预先选中；支持交付范围内的六类型、精确字段/成员和元信息。名称查找要求明确 MATCH，返回候选及实际覆盖范围。无连接、无有效目标、缺失、无权限、截断和预算耗尽分别返回。

**验收**：核对明确 Key/字段、无选中或面板收起、多候选、无匹配、空页续读、取消、目标变化和错误的工具参数、命令、结果及传递。部分值必须标记不完整。自然语言的业务含义推断和追问质量不参与插件评分。

## 2. 在指定范围筛选和汇总

**工具要求**：按确认的连接、DB、MATCH、字段及精确比较值有界查询；续读条件保持一致，不返回未匹配字段值。正确记录检查、匹配、缺字段、类型不符、缺失及失败计数；累计计数与匹配名称去重使用实际记录。

**验收**：对照合成数据及实际调用核对多页结果、空结果、缺字段、类型变化、权限失败、取消、超限和并发变化。结果提供扫描状态、读取时间范围及非快照说明；不要求模型在最终回答里复述这些信息。

## 3. 提供诊断信息

**工具要求**：提供 Key 元信息、内存、服务器/DB 概况、慢日志、客户端、消费组及有限比较等已有只读采样。区分缺失、未知、不支持、无权限、空结果、部分结果和失败。明确请求时保存选定的已有诊断报告。

**验收**：核对数值、单位、时间、读取范围及错误，报告与选定原采样一致且不含凭据或未经选择的值；不清日志、踢连接、改配置或推进消费。插件返回必要的采样限制，不负责模型的故障归因、历史推断或建议。

## 4. 按需在界面核对

**工具要求**：打开面板、定位目标、读取当前选择、单次刷新、格式切换及 MATCH 预设使用真实接收端回执。用户新操作优先；保留二进制和 Stream 字段身份，不自动开启持续刷新。

**验收**：对照原始工具回执与实际插件界面。刷新须绑定本次读取、目标与渲染结果；覆盖旧结果、读取中、隐藏/关闭、多接收端、选择变化、取消、失败、超时、回执丢失和目标失效。无有效确认不得返回 applied。未取得真实后台或丢回执证据的场景继续标注未覆盖，不以模型说“已打开”代替回执。

## 5. 连接和环境

**工具要求**：仅使用当前会话及已确定的资料，凭据由本地受控表单处理；正确执行连接、候选交换、切 DB 和断开。失败保留旧连接，会话隔离与连接代次校验有效。

**验收**：核对唯一目标、同名资料、缺凭据、失败、切换、取消、超时、并发和资源释放；认证失败的工具分类正确，失败后旧连接状态和实际读取一致。模型如何解释认证根因不属于插件验收。mTLS、SSH、Sentinel、Cluster 按实际需求另行实施，未支持的模式不宣称支持。

## 6. 专业数据

**工具要求**：RedisJSON 路径、TimeSeries 范围、Bitmap 位范围、GEO 坐标/距离和消费组复用既有只读服务，保留大整数、null/无匹配、时间、单位、未知 lag 及分页身份。

**验收**：在相应服务/模块核对原始数据和工具结果，覆盖模块缺失、无权限、空结果、上限、取消及目标变化；确认结果送达模型。图形仅显示实际样本，不执行写入或消费推进；模型对专业数据的解读不计入插件验收。

## 7. 成品交付与案例

**工具要求**：文档与实际接口一致；记录源码、包哈希、安装及加载结果，包内不含秘密、业务数据或临时配置。连接资料保留、卸载及实际支持环境按各自范围记录。本地交付不等于公开发布。

**验收**：代码变更执行相应类型检查和回归，正式打包执行默认完整检查；在 DSH 中核对工具可发现、可调用，原始结果进入后续模型上下文。独立 profile 检查安装、卸载与资料保留，不能代替真实调用链路。

[四个公开案例](verification/enterprise-cases-research-2026-11-05.md)只用于构造工具场景：广告 Key 的值/TTL/缺失、SCAN 续读与范围、认证失败与旧连接保持、服务器概况与慢日志。核对实际调用、返回信息和传递链路，不要求模型正确复现案例分析；本机合成测试不宣称复现企业生产环境或规模。

## 记录与维护

- 原始工具记录是数据核对依据；模型回答可作为联调附录，不设自由文本准确率或回答通过门槛。
- 真实联调默认使用隔离合成数据；业务数据进入模型前须明确连接、目标与范围。禁止写值、改 TTL、删除或推进消费；禁止借其他工具绕过权限与预算。
