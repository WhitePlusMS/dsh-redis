## 当前基线

当前代码已有显式 Key、Hash 字段、Set/ZSet 成员读取，名称扫描、有界 Hash 字段精确筛选、诊断报告及部分连接和界面工具。报告保存用户选定的原始诊断采样，不重新读取；名称扫描要求明确 MATCH，文本身份及范围参数会严格校验。源码 `4eafb8d` 的开发包通过隔离 profile 安装卸载检查，但后续源码已修改，包须更新，详见[开发包记录](verification/current-development-package-2026-11-04.md)。日常 DSH 和用户模型已对较早构建通过部分合成数据读取、搜索和筛选；界面动作通道及预算接口失败，当前源码的真实验收仍未完成，详见[此前记录](verification/user-questions-real-model-2026-11-04.md)。旧记录只对应各自构建。

## 1. 直接查询与查找对象

**用户问题**：“`user:123` 的状态是什么？”“订单 1001 的缓存在哪里？”

**状态：部分场景已通过真实模型，完整节点待验收。** 当前构建的六种基础类型已通过独立 Redis 与真实 ToolRuntime 的无选中直接查询，覆盖 String 截断、缺失 Key 和 Stream 重复字段；独立 Redis 的真实 ACL 测试覆盖允许读取以及 HGET、SCAN 被拒绝。较早构建的显式 Hash 字段、Set/ZSet 成员和名称候选已用真实模型验证。当前构建的真实模型及其他异常组合仍待验收。

**完成内容**：当前会话连接/DB 明确时，不选中 Key 即可读取已知对象及必要字段、成员和元数据；用户提供线索时，在指定范围搜索并返回候选、查询模式与覆盖范围。无连接、目标不存在、候选不唯一、无权限、截断和预算耗尽分别说明；线索不足时请用户补充，不猜业务含义或自行跨库。

**验收**：真实 DSH 和用户模型读取合成 Key 与字段，测试面板关闭或无选中；覆盖多候选、无匹配、空扫描页续读、取消、目标变化和错误。六种基础类型按实际交付范围核验，部分值不称完整值。

## 2. 在指定范围筛选和汇总

**用户问题**：“在 `order:*` 中查找状态为 failed 的订单。”

**状态：Hash 单字段精确筛选已通过隔离专项与真实模型两批合成数据验证；异常组合和完整节点待验收。** 不代表支持任意表达式或完整数据库统计。

**完成内容**：按用户指定的连接、DB、Key 模式和必要字段有界筛选；控制扫描、读取次数、字节、时长与续读，输出检查数、匹配数、跳过/失败数及时间范围。避免把不相关原始值发送给模型；部分扫描和并发变化明确说明。

**验收**：真实模型调用当前构建筛选合成订单并正确解释范围；覆盖多页、缺字段、类型变化、权限失败、取消、超限和并发变化。SCAN 可能重复，完成也不是原子快照。

## 3. 根据证据排查问题

**用户问题**：“这个 Key 为什么查不到？”“有没有慢查询？”“消息组是否积压？”

**状态：元数据和部分界面诊断已有基础；显式 Key 内存估计、有界慢日志、服务器概况、客户端连接诊断、Stream 消费组采样及两个 String 的有限比较已通过隔离 Redis 与工具专项。上述六类采样可按用户明确要求保存本地报告，工具专项覆盖会话隔离及字段范围；当前构建真实模型验收待完成。**

**完成内容**：按问题复用 Key 类型、TTL、长度等信息；按实际需求和权限提供内存、服务器/DB 概况、慢日志、客户端、Stream 消费组及有限比较。区分证据、推测、无权限、不支持、空结果和失败；用户明确要求时可将选定结果保存为本地报告。

**验收**：在隔离数据和真实模型下逐项验证已交付诊断，记录时间与读取范围；大响应、权限和不支持必须明确。报告不含凭据或未经选择的值；不清日志、踢连接、改配置或推进消息消费。

## 4. 按需在界面核对

**用户问题**：“打开刚查到的 Key。”“解释我选中的字段。”“刷新并以 JSON 查看。”

**状态：部分动作、选择同步和定位有实现及历史专项；当前真实 DSH 中动作通道和选择同步失败，须排除宿主旧接口清单并重验。AI 单次刷新已按读取身份重做，String、Hash、Set、ZSet 和 Stream 的浏览器延迟刷新及 List 的真实工具/宿主流专项通过；AI 值预览格式已接入六种基础类型，String、Hash、Set、ZSet、Stream 浏览器及 List 宿主流专项通过。已保存 MATCH 预设应用通过真实工具、Host 流和浏览器贯通专项，覆盖正常应用及用户抢先输入；结果仅表示筛选已设置并启动扫描。上述使用合成数据，当前构建的真实 DSH/模型验收及其他类型覆盖仍待完成。**

**验收**：真实 DSH 中逐项核对实际界面与模型结果；单次刷新须通过读取身份绑定完成结果与实际渲染，覆盖旧结果仍在、读取未完成、面板隐藏或关闭、多接收端、用户选择变化、取消、失败、超时、回执丢失和目标失效。无有效回执不得声称已应用，不自动开启持续刷新。

## 共同行为

- 单次及连续读取均有预算；绑定会话、连接代次、DB、目标和续读条件。读取期间切换目标、结果过期、取消及权限失败不得伪装成功。
- 真实模型验收使用隔离合成数据；业务数据发给模型前明确连接、目标及范围。不得修改 Redis 值、TTL、Key 或消费状态，也不提供自由命令或脚本。
- 每节点先做类型检查和相关测试，再用当前构建、真实 DSH 与用户模型验收；记录实际工具调用及未覆盖项。按完成节点更新 `UPDATE_LOG.md` 并创建本地 Git 提交，不自动推送。
