# RO07 界面动作与回执契约草稿

状态：RO06 已完成，RO07 进行中。动作协调器、通道和 Client 接收代码已实现；真实 DSH 的面板打开已验证，其他界面动作及选择竞态尚未完成，本草稿不代表 RO07 完成。

## 固定版本依据

- 基线为 DSH `0.2.0-rc.2`，本地上游源码和证据见 [RO01 契约记录](readonly-ro01-contract-2026-10-28.md)。
- 固定版 [API Gateway 文档](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.0-rc.2/docs/api-gateway.zh.md) 描述 Client 主动打开双向 Remote 流、Host 接收上行项、取消以及作用域身份解析。该接口不自动选出唯一的 Redis 界面。
- 宿主应用控制远程事件转发的事件源；Gateway scoped waterfall 会向多个 Client 分发，不能单凭第一个回执证明目标界面唯一。因此不假定插件自定义事件可直接被转发，也不把 `hasLiveClient()` 当作界面已就绪。
- [右侧栏接口](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.0-rc.2/packages/client/ui-sidebar-right/README.zh.md) 提供 Client 侧打开能力；Host 不能据此直接调用该接口。面板尚未挂载时，是否存在可接收请求的 Client 注册点需在原生装配中验证；无法确认时应要求用户先打开面板。

## 拟定最小契约

1. 会话身份由宿主 Agent 上下文确定，不能由模型传入任意会话 ID。Client 通过已有 Remote 流主动登记自身；Host 按会话维护有界、可清理的活动接收者状态。
2. 每项动作至少包含请求标识、动作类型、目标连接和视图代次、有效期限及必要参数；需要保护当前选择的动作还携带选择版本。请求标识仅关联一次请求与回执，不承担持久队列职责。
3. 没有可用接收者或同一会话存在多个无法唯一确定的接收者时拒绝自动应用；不得以随机选择、广播首个响应或活动连接存在代替唯一性。接收者断开后清理登记和未完成请求。
4. Host 派发前校验会话、接收者、目标代次及期限；Client 执行前再次校验自身仍挂载、目标仍一致、期限未过和用户选择版本未变化。用户后续手动操作优先，迟到请求不得覆盖新选择。
5. Client 实际执行后回传与请求标识、目标代次对应的终态；只有确认 `applied` 才能报告界面已应用。未挂载、目标变化、无唯一接收者、不支持、取消、超时和执行失败应有可区分结果；派发或收到消息不等于成功。
6. Host 和 Client 都对取消、断流、会话释放及超时做清理，迟到或重复回执不得改变已终结结果。不得引入无界轮询、持久动作队列或额外消息系统。

## 验收前的待验证问题

- 当前插件的 Typert 贡献能否在固定版 DSH 真实 Host/Client 中挂载双向流，并在会话切换、Client 卸载、断网和重连时可靠释放。
- 侧栏被关闭时，是否仍有可靠的 Client 注册点可调用原生打开接口；若没有，产品行为为提示用户手动打开，不能宣称已打开。
- 两个窗口同时打开同一会话、窗口关闭和用户快速更改选择时，接收者数量、目标版本与执行回执能否正确收敛。
- 需通过单元/真实 Host 装配和原生界面交错验证未挂载、目标失效、重复/迟到回执、取消及超时；模型对话结果与脚本结果分别记录。
