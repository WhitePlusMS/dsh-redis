## 待修正及未覆盖

- 模型将 `TTL = -1` 解释为“从未设置过期时间”；该值只能说明采样时无关联过期时间，不能证明历史。模型还把本次 SCAN 结果称为完整的唯一集合，未说明并发变化下扫描不是一致性快照。两项回答准确性待修正并用当前构建复验。
- `b40d164` 提示更新后，在新会话真实模型复验 TTL：模型仍把无过期时间说成长期保证，并无依据推断业务地点、状态与时间时区，还建议修改 TTL；因此提示本身没有通过准确性验收。随后新增不读取值的 Key 元信息工具，需在新构建中继续验收。
- 新工具对应源码 `4175196`，开发包 SHA-256 为 `ccccc8b0fca5a09cf381f8689ab92c3a42d45941b21c953a261f42be90789ec5`；日常 profile 已安装的 135 个文件与包一致。新会话中模型实际调用 `redis_viewer_key_metadata`，工具返回类型和 TTL，不含字段或值；UTC 时间也被正确标注。模型回答却在同一答复内先推断从未设置 TTL、永久保留，后又正确说明无法推断历史，且继续猜测业务含义并建议写入。故元信息最小读取通过，回答准确性仍未通过；已停止继续叠加提示补丁，需要重新审视输出方式。独立 Redis 工具验证通过不替代这一真实失败。
- 同一构建的真实诊断请求实际调用服务器概况、慢日志和指定 Key 内存工具，并取得采样数据；模型回答却从单次指标无依据断言内存状态和慢日志阈值、给出过度确定的风险结论及配置建议。工具调用有结果不等于诊断结论正确，本场景回答准确性未通过，不应据此改业务配置。
- 真实客户端明细查询调用 `redis_viewer_clients`，工具返回服务器范围、采样时间、总数和完整状态；模型复述了这些字段，却额外断言某条连接对应当前查询会话，工具结果没有提供该对应关系。此场景的回答准确性未通过。
- 对真实 Hash 请求 Stream 消费组，模型调用 `redis_viewer_stream_groups`，工具报告类型为 Hash、状态为 `unsupported`、组数未知；模型正确说明不能查询其消费组。本次仅覆盖非 Stream 类型边界，未覆盖真实 Stream、消息读取或消费推进。
