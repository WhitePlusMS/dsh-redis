# RO05 分页与预算阶段验证记录

日期：2026-10-28，更新于 2026-10-29。RO05 已按其分页、预算和部分数据条件验收；阶段真实模型对话仍属于 RO06。

## 实现范围

- 单次 RESP/Key 页、界面缓存、AI 单次结果、AI 会话累计调用和字节分别限制。AI 工具使用可信 DSH 会话身份；用户在侧栏主动恢复预算，目标切换不重置累计预算。
- AI Key、Hash、Set、ZSet 扫描和 Stream 对已收到的大页分块，完整返回身份；Stream 按整条消息切分，保留重复字段顺序，并同时遵守 `count` 和结果字节上限。不可分单项超限明确拒绝。
- Hash、Set、ZSet 扫描和 Stream 使用有界候选与已提交状态，避免旧类型探测、取消或失败破坏较新的有效续读。连接、数据库或选中项失效时拒绝旧结果。
- 界面自动扫描达到单轮页数/时间限制后，可由用户手动从完整保存的游标继续；缓存超限已丢弃批尾时明确停止并要求缩小筛选。失效游标保留已加载部分，提示用户手动刷新。

## 实际检查

- 当前代码 `pnpm check` 和默认 `pnpm pack` 的预打包检查均通过：30 个测试文件、330 项测试。测试包括本机 Chrome 的 React 组件夹具：暂停后双击仅续读一次、失效时保留已加载列表并展示中英文提示。
- 使用隔离临时 Redis、正式 TCP transport 和注册后的 DSH ToolRuntime，分别验证合成 Key 140 个（3 次）、Hash 字段 140 个（6 次）、Set 成员 140 个（3 次）、ZSet 成员与整数分数 140 个（3 次）、Stream 消息 80 条（5 次，每条两个同名字段）。每次工具结果均不超过 64 KiB，完整身份与预置集合一致；临时实例均由夹具关闭。各项测试针对运行时当时的对应构建；部分发生在后续通用协调器重构之前。
- 当前包安装于项目内隔离 DSH profile。真实 DSH Web 侧栏加载后可见预算状态；只读连接本机 Redis 时，DB 0 显示已加载 760 个 Key。另在自建临时 Redis 写入 150,000 个合成短 Key，预先以同一 MATCH 和 COUNT 检查得到约 1,495 个扫描批；DSH 筛选不匹配的条件后显示“本轮扫描已暂停”，点击“继续扫描”后显示“扫描完成”。临时实例按夹具流程关闭。此界面验收未调用真实模型。
- 用户日常 profile 的已安装版本完成真实模型调用，详见 [独立记录](readonly-real-model-installed-2026-10-28.md)；其 AI reader 哈希不同于当前工作区构建，不作为当前版本的真实模型证据。
- 2026-10-29 使用当前构建、隔离临时 Redis 的 141 个合成 Key 和正式注册的 ToolRuntime：先调用状态工具 31 次，再请求第一页以耗尽 32 次预算；下一次续读提示预算用完并保留游标。另一会话不能恢复该预算，本会话人工恢复后沿用原游标读完，两页合计 141 个 Key；另一个会话状态显示未连接。此项通过脚本调用工具，未调用真实模型。首次运行误给 Key 工具传入不支持的 count 参数，工具拒绝；按实际 schema 移除参数后重跑通过。
- 当前构建在同一独立 Redis 上交错执行 UI Key reader 与 AI Key reader，两套游标独立续读，分别读取的 141 个 Key 身份一致。分页、预算、各类型及浏览器专项重跑 11 个文件、141 项通过；空页、重复身份、截断和目标变化等确定性交错由自动测试覆盖。

## 边界与待验收

- 当前版本的预算耗尽恢复已用隔离 Redis 和正式工具实测；真实模型对话仍需覆盖预算恢复、取消与跨会话目标切换，归入 RO06。早期版本的真实模型多页及当前版本修正说明后的切库复测见 [RO06 记录](readonly-ro06-real-model-2026-10-28.md)。真实 DSH 界面的扫描预算暂停与手动继续已通过上述合成实例验证。
- 同一 DSH 会话的多个 UI 面板共用 Key 扫描所有权；一个面板刷新可使另一面板旧游标失效。该面板提示扫描状态失效并要求手动刷新，不自动跳页。
- List 与 ZSet 排名结果若整批超出 AI 单次预算会明确拒绝，用户可缩小范围；超出预算且无法完整表示的单项也会拒绝。
- Host 已提交工具结果后，若宿主或网络丢失响应，当前实现无法确认模型是否收到，也不保证旧令牌可自动重放。
- 未因此记录而自动安装日常 DSH profile、提交、推送或发布。
