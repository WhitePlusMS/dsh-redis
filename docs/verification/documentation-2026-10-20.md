首次打包的默认检查通过后，发现开发说明中的官方工具文档路径使用了错误目录；已改为实际的 `packages/core/tools/README.zh.md`，并重新执行默认打包。表中SHA指向修改后的最终包。

临时核包脚本最初把 JSON 键顺序当成 manifest 差异，且错误地向 `pnpm remove` 传入 `--offline`；这些是检查脚本问题，未修改产品来迁就脚本。安装与卸载指南中的正式命令没有这个无效选项。进一步发现脚本对 DSH profile 清单内部结构作了不必要假设，随后移除内部结构检查，直接使用官方配置打印验证组合结果。失败轮次不计入上表的两次完整安装/卸载循环；各轮所属home均通过 finally 清理。

独立home未复制任何用户配置或模型凭据，仅为资料保留检查写入 `{"version":1,"profiles":[]}`；没有连接Redis。重装循环验证的是同一个开发包的卸载/重装步骤，不冒称两个不同正式版本间的升级或降级兼容性。
