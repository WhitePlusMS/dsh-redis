## 认证与超时

认证尝试的原始回执 UTC `01:47:46.384Z` 为 `failed/auth`，`previousRelease=null`、`connection=null`。失败前后 A 的连接 ID 相同、generation=5、DB0、目标 3810。随后 value 在 `01:47:48.589Z` 返回完整 22 字节 `synthetic-string-value`。因此证明旧连接可用，未证明单凭 auth 分类即可确定认证失败的具体配置原因。模型把它断言为缺少凭据，并称旧连接“已认证”，超出状态结果的证据。

首次延迟尝试：代理连接 1 在 `01:49:31.809Z` 收到并持有 PING 响应；工具 `01:49:39.778Z` 返回 `failed/timeout`，代理 `01:49:39.794Z` 观察到关闭，约 8 秒。Redis 客户端数由等待中的 5 回到 4（A、B、夹具管理、代理管理）。状态仍是原 ID / generation=5 / DB0，`01:49:41.091Z` 读取同一合成值成功。

随后为捕获取消窗口又发起三次显式请求，均先到约 8 秒超时：连接 2、3、4 对应工具采样 `01:50:16.438Z`、`01:51:29.688Z`、`01:54:20.528Z`。前两次未赶上点击停止；第三次只停止了超时后的模型输出。这三次不计为连接取消通过，不是模型自动重试。

## 真正取消、交换与隔离

下一次请求使用同一浏览器操作批次等待连接工具显示运行中并立即点击停止：代理连接 5 于 `01:54:46.405Z` 确认响应已被持有，`01:54:46.775Z` 观察到套接字关闭，约 0.37 秒，明显早于握手超时。界面显示已停止；该调用的轨迹结果为 `error`，详情为 `Error: [object Object]`，不把它改写成已收到结构化 cancelled 回执。

取消后客户端数回到 4；独立新调用在 `01:55:06.080Z` 确认旧 ID / generation=5 / DB0 / 3810，`01:55:06.594Z` 再次读取完整合成值。B 在北京时间 09:55:03 刷新成功。连接取消与原连接保留的结论来自代理和后续状态、读取的联合证据。

解除持有后再次连接，`01:55:40.004Z` 返回 `connected`、`previousRelease=closed`，会话连接 ID 保持，generation=7，DB0；状态目标为 8939，`01:55:41.212Z` 值读取成功。代理连接 6 除 PING 外，还观察到侧栏初始化的 DBSIZE / INFO / CONFIG / SCAN，以及值读取相关命令。不能将模型“未读取其他 Key”的说法扩展成侧栏没有加载名称。模型称端口变化证明“另一实例”，实际两个端口到同一 Redis，该结论错误。

随后模型先查询 A 状态，再以该 ID 和 generation=7 调用断开；`01:56:54.200Z` 返回 disconnected，代理同刻观察到连接 6 关闭。客户端数降到 3。B 在北京时间 09:57:15 仍刷新出完整值，保持 3810 / DB0；因此本次 A 断开没有断开 B。最后手动断开 B，客户端数为 2，仅剩两条管理连接。成功交换后旧连接释放由回执与断开后的客户端数量共同支持，不声称精确记录了旧直连套接字关闭的瞬间。
