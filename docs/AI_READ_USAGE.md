# 在DSH对话中读取Redis

## 使用顺序

1. 打开目标DSH会话的Redis侧栏，手动连接服务器。连接仅属于这个会话；保存的资料不代表已连接。
2. 选择DB及Key。如果问题指向一个具体字段或元素，先在现有表格中选中这一行；Stream还可选择消息中的具体字段对。
3. 回到同一会话输入问题。无需复制Key名称、值或导出快照。模型服务及该会话的工具策略必须可用。

可使用这些自然语言请求；它们是操作示例，不是本次真实模型验收记录：

- “当前Redis连接到了哪里，当前DB是多少？”
- “检索当前DB里符合 `order:*` 的Key，先告诉我本批结果。”
- “读取 `order:1001`，解释其中的字段。”
- “解释一下我在侧栏选中的当前这个值。”
- “明确切到DB1，再查询 `order:1001`。”

普通查询保持当前DB。没有连接或没有有效选择时，工具会返回对应错误，不能猜测其他服务器或旧选择。切库之后，侧栏跟随Host的实际DB；旧选择与旧自动刷新随代次失效。

## 当前选择如何解释

| 侧栏选择 | 不传Key的值工具读取 |
|---|---|
| String或仅Key | 当前Key的默认有界读取 |
| Hash字段行 | 精确字段的当前值 |
| List行 | 原始下标对应的当前元素；List可变，下标不代表不可变记录ID |
| Set成员 | 检查该原始成员仍存在后返回成员 |
| ZSet成员 | 该原始成员和当前原始分数字符串 |
| Stream字段对 | 消息ID、字段出现序号和原始字段身份对应的当前值；重复字段不合并 |

选择同步只发送标识，不发送值；状态工具给出最后同步时间。读取时重新访问Redis，并核对会话/连接代次和读取期间的选择变化。工具提供读取时的数据，不是事务快照。显式传Key的查询不依赖侧栏当前选行。

## 四个官方工具

| 工具 | 主要参数 | 返回与限制 |
|---|---|---|
| `redis_viewer_status` | 无 | 当前公开连接视图、DB、最后同步的选择及时间 |
| `redis_viewer_keys` | 可选`match`、`cursor` | 当前DB的SCAN批次；续读保持同一MATCH，空页不一定结束 |
| `redis_viewer_value` | `key`或`keyBase64`可省略；按类型提供范围/游标 | 六类型结果、TTL、读取时间、完整性和续读信息 |
| `redis_viewer_select_db` | 必填整数`db` | 同一连接的实际切库结果；仅明确要求切库时使用 |

Key文本和Base64身份只能传一个。位置及Stream ID使用字符串以保持整数精度。值工具支持String的`offset/bytes`、List及ZSet排名的`offset/count`、Hash/Set/ZSet扫描的`match/cursor`、Stream的`start/end/direction/count/cursor`；参数仍由各类型严格校验。

AI与UI独立持有游标，复用所属会话的同一连接；AI内部也遵循每类型一次扫描的现有所有权约束。对话单结果上限64KiB，集合值默认前4096字节，String默认4096字节。字段/成员身份不截断；超预算明确失败，不能跳过本批尾部后继续游标。`scanComplete`说明扫描结束，`complete`说明本次结果是否完整，二者不同。

二进制值保留Base64和字节长度，不能当作损坏文本；UTF-8前缀不完整时文本可能为空。未读取字节、其他分页及过滤掉的字段都不应被模型当作已知。

## 只读及运行边界

工具不接收sessionId或自由命令，不自动建立连接，不返回密码，也不新增快照、诊断或特殊类型。DB切换只影响所属连接的逻辑DB，不修改Redis业务数据。连接断开、代次变化、会话或插件释放会清理AI选择及游标。

实现遵循固定rc2的[官方工具契约](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/docs/cookbook/adding-a-tool.md)。实际检查、模型服务故障与日常安装状态见[实施记录](AI_READ_IMPLEMENTATION.md)；自动化或脚本模型通过不等于真实模型自然语言验收通过。
