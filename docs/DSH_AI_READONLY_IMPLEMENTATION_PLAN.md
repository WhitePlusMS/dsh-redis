# DSH Redis AI 只读实施方案

更新日期：2026-11-02。本文是当前实施方向；具体任务及状态见[任务清单](DSH_AI_READONLY_TASKS.md)。文中列出的目标是计划，不代表当前版本均已实现或通过验收。

## 目标

让用户在 DSH 对话里直接提出 Redis 查询或排障问题，AI 使用当前会话中明确的 Redis 连接，调用插件提供的只读能力取得证据，再根据实际结果回答。用户不需要为了普通查询先打开插件界面或手动选中 Key。

例如：“`order:1001` 里是什么”“找出 `order:*` 中状态为 failed 的订单”“这个 Key 为什么查不到”“看看最近有没有慢查询”。这些是需要验证的使用场景，不表示已经做过用户频率调研，也不表示现有版本已经能完整回答。

界面仍用于人工浏览和核对：用户要求“打开刚才那个 Key”时才联动界面；用户说“解释我选中的字段”时使用当前选择作为上下文。没有可用界面时，明确目标的普通读取仍应工作。

## 用户如何完成一次任务

1. **确定范围。** 使用当前对话已经建立的连接和当前 DB；若未连接则引导连接。用户未明确要求时不自行切连接、跨 DB 或扩大搜索范围。目标或业务线索不足时，请用户补充，不能猜测服务器、DB 或 Key。
2. **找到目标。** 对用户给出的准确 Key 直接读取；对明确的前缀、模式或线索进行有界候选查找。Redis MATCH 是 Key 名字符匹配，不理解业务含义，也不按值搜索；多个候选或证据不足时展示候选及已覆盖范围，不擅自认定。
3. **读取和分析。** 按问题读取必要的值、字段和元信息。针对用户明确范围内的批量筛选或比较，只读必要数据；预算耗尽、权限不足或目标变化时保留部分结果和原因。
4. **给出答案。** 区分实际读到的事实、推测和无法判断的内容，说明连接目标、DB、采样时间、结果范围及是否完整；不能将有限样本、截断数据或并发变化中的扫描描述为完整快照。
5. **按需核对。** 用户希望在界面查看时定位真实目标并等待界面回执；用户正在手动选择时尊重其新操作，迟到动作不能抢回选择。

## 需要交付的能力

| 用户目的 | 实施内容 | 完成后的可核验结果 |
| --- | --- | --- |
| 直接看一个对象 | 按明确 Key 读取类型、TTL、长度、内容及必要字段或成员；逐项补齐六种基础类型的实际缺口 | 无需面板选择，真实模型能基于读取结果回答，并正确说明缺失或截断 |
| 不知道完整名称 | 在用户提供的连接、DB 和名称线索范围内有界搜索，支持明确的候选与续读 | 无匹配、多候选、部分扫描和歧义均被准确说明 |
| 在范围内查找或比较 | 按用户指定范围读取必要字段，筛选、汇总或比较已读数据 | 记录检查数、匹配数、失败或跳过数、时间及覆盖；部分结果不说成全部 |
| 解释异常 | 按问题提供 Key 信息和可用的服务器、慢日志、客户端及 Stream 消费组只读诊断 | 以实际证据回答，权限不足、能力不支持和原因未知分别说明 |
| 人工查看结果 | 按需打开面板、定位 Key 或字段；支持读取用户当前选择 | 界面确认后才报告已应用；不阻塞不依赖界面的读取 |
| 管理使用环境 | 按明确请求使用已有连接、切换 DB、刷新、切换预览格式、保存筛选或导出已选诊断报告；必要时补充连接方式 | 目标身份明确，凭据由本地界面处理，失败不悄悄换环境 |

常见 Key 读取、搜索和分析先构成可交付闭环。诊断、界面联动与连接管理依据具体场景逐项验证。mTLS、SSH、Sentinel、Cluster，以及 RedisJSON、TimeSeries、Bitmap、GEO 等只在实际环境或数据需求需要时安排；若当前连接本身依赖其中一种，可将该连接能力前移。未使用的模式或模块不阻塞无关能力交付，也不得被描述为已支持。连接选型和各模式验证边界见[连接扩展技术方案](RO21_CONNECTION_ARCHITECTURE_PLAN.md)。

## 实施起点

- 当前实现已有 DSH 原生工具查询连接状态、按 MATCH 搜索 Key、读取指定 Key 和按明确请求切 DB；不传 Key 的读取使用当前界面选择。显式读取工具存在，不等于所有自然语言问题已完成端到端验收。[工具实现](../src/host/ai-tools.ts)
- 会话身份、连接及代次校验、有界读取、独立的 AI/UI 游标、六种基础类型 reader 均有既有实现，可在核验后复用；界面动作和已有连接管理只有部分实现。[AI 读取服务](../src/host/ai-reader.ts)
- 历史验证记录只对应当时的构建和环境；不能证明后续工作区或全部场景通过。[历史真实模型记录](verification/readonly-ro06-real-model-2026-10-28.md)
- 暂停前未完成的筛选预设工具接入存在两处 TypeScript 错误，当前工作区不能视为可交付构建。恢复代码工作时先修复并核验，再依据新任务清单推进；不因已有投入继续优先建设低价值功能。
- 宿主/SDK 使用项目固定的 DSH `0.2.0-rc.2` 契约，正式 Redis 连接为项目现有 TCP/TLS、RESP2 传输；依赖中存在 `redis` 包不代表已支持 Sentinel 或 Cluster。实施时核对相应固定版本的官方文档，不能套用未经验证的新接口。

## 架构和正确性

DSH 负责理解请求、选择插件工具和组织回答；插件 Host 负责会话、目标、命令、预算与实际 Redis 读取；界面通过现有 RPC 复用 Host 能力。工具和 UI 不各自复制 Redis 查询实现，不新增独立聊天窗、模型调度系统或任意命令后门。

- 会话身份来自 DSH 执行上下文，模型不能指定任意其他会话；请求绑定连接、代次、DB 以及原始 Key/成员身份。排队、发送及返回时核对目标，切库或换连接后旧请求和游标失效。
- 对话只使用经过校验的固定只读命令及参数；Redis 内容只是数据，不能因 Key 或值中的文字改变工具权限或执行指令。取消后不能声称已发出的命令被撤回。
- 每次结果和连续调用均有预算；实施前明确扫描批次、候选数、读取次数、字节、时间和续读归属。预算耗尽后停止并说明，用户明确继续时遵守累计规则，不能靠分页、多次调用或多节点绕过。
- Redis SCAN 可能重复或返回带游标的空页，完成扫描也不是并发一致性快照；扫描是否完成、内容是否完整和界面是否应用分别报告。二进制身份保留原始字节，长整数不失精度，Stream 同名字段保留顺序身份。
- 明确目标的读取独立于面板可见性。界面动作需要有效目标和实际回执；多个接收端无法唯一确定时不得假报成功，用户的新操作优先于迟到结果。
- 连续两次以上补丁仍未解决同一问题时停止修补并重新审视方案；新增 TypeScript 遵循现有严格类型、共享 DTO 和命名风格，不使用 `any` 或旧协议兼容兜底。

## 数据、权限与只读边界

读取仍可能消耗资源或影响 Redis 自身统计，不能承诺零影响。所有读取按 Redis ACL 和实际能力执行，不调用 shell、其他插件或提升权限来绕过限制。

Key、值、慢日志参数和客户端信息进入工具结果后，可能进入 DSH 对话及其配置的模型服务。只返回回答问题所需的数据；真实业务数据进入模型前必须明确连接、目标和数据范围。真实模型验收默认使用隔离的合成 Redis 数据，不向日志、对话、报告或工具参数暴露密码、私钥、口令和带凭据的 URI。

本轮继续暂缓修改值、TTL、删除或重命名 Key、导入 Redis、消息 ACK/claim/消费推进、消费组修改以及服务器配置或故障切换。也不提供自由命令、Lua、Functions、清空慢日志、杀连接或自动修复。插件的本地连接资料、筛选预设或报告仅在用户明确请求时按受控范围保存，不作为 Redis 业务写入。

## 按用户问题验收

每个交付节点先进行 TypeScript 类型检查，再运行相关专项；阶段交付执行项目完整检查。测试数据准备和插件运行命令分开记录，验证只读边界。界面变更使用真实 DSH 界面核验，模拟浏览器和单元测试不冒充真实使用。

真实 DSH 与用户现有可用模型按用户问题逐项验证，记录构建和包哈希、Redis/DSH 版本、模型、实际工具调用、输入范围、回答、完整性和未覆盖项。至少覆盖：

- 不选中 Key 直接读取明确目标和字段；Key 不存在、类型变化、未连接、无权限与数据截断。
- 通过名称线索查候选；无匹配、多候选、空页带游标、继续、取消和预算耗尽。
- 在指定范围内筛选及比较；候选消失、字段缺失、类型变化、部分失败与并发修改。
- 对已交付的诊断、界面定位和连接行为分别验收；界面隐藏、多接收端、用户抢先操作和旧动作返回按适用场景覆盖。
- 恶意指令样式的数据不得改变权限；用户请求写入时明确不支持。未安装模块、权限不足、网络错误和部分节点不可达不能冒充空结果或成功。

每个验收合格的节点更新 `UPDATE_LOG.md`，记录文件、原因、影响和验证，并按用户要求分别创建本地 Git 提交。不自动推送或发布。正式交付前对当前构建执行打包、安装、使用和卸载验证，明确实际支持范围；历史构建的通过记录不替代当前成品验收。

测试和验收优先确认用户实际使用的 DSH 环境；隔离合成数据不要求把临时宿主冒充用户日常实例。不得擅自改动或关闭用户已有 Redis、DSH 和其他服务；只清理本任务创建并可确认所有权的资源。
