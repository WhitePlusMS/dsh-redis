# DSH Redis AI 原生能力只读实施方案

初版日期：2026-10-28；调整日期：2026-11-02。状态：实施进行中，按用户问题重新安排优先级；具体状态与证据以任务清单和验收记录为准。

本方案面向 DeepSeek Harness（DSH）原生 Redis 插件：由 DSH 自带的 AI 理解用户请求，调用插件提供的查询、界面、连接和诊断工具；插件负责真实 Redis 访问、权限与范围校验、结果返回和界面展示。界面操作与 AI 调用复用同一套 Host 能力。

用户已授权开始实施非 Redis 写入内容；原第 3 阶段安全编辑整体暂缓。完整任务依赖、范围与验收条件见[任务清单](DSH_AI_READONLY_TASKS.md)。

## 1 目标与范围

### 1.1 从用户问题到可验证的答案

用户的目标是找到数据、理解内容或排查问题；Key 定位、选行、切格式和刷新是按需使用的辅助动作。下面是待验证的使用假设，不代表已完成用户调研或真实场景验收：

1. **明确 Key 直接查询**：用户说“看看 `order:1001` 是什么”或询问其 TTL；当前会话已有连接时直接针对当前 DB 读取，无须先打开面板或选中 Key。
2. **依据线索发现候选**：用户只知道前缀或业务线索时，在明确范围内有界查找候选；名称可能不唯一或线索不足时，展示候选、已扫描范围并请用户补充，不能猜选。
3. **范围内筛选与比较**：用户提出“在 `order:*` 中找状态为 failed 的订单”或比较指定 Key 时，只读取任务所需字段，标明检查数量、覆盖范围、截断和采样时间；不能把有限样本说成全库结论。
4. **根据证据诊断**：用户询问过期、慢查询或消息积压时，按实际能力和权限取得有界证据；区分事实、推测与不能回答的部分。
5. **按需界面核对**：用户要求“把结果打开”时定位界面；用户说“解释当前选中项”时才依赖面板上下文。界面不可用不应阻塞显式目标的普通读取。

Redis MATCH 只能匹配 Key 名字符模式，不是业务语义搜索或按值搜索；用户线索不足时不能凭空确定 Key、连接或 DB。连接和切 DB 保持明确意图，不为普通查询自行切环境。以上体验是规划目标，不等于现有实现或真实模型已覆盖。

不新增模型供应商配置、独立聊天窗、AI 调度引擎、预设业务工作流或 MCP 服务。分析和自然语言总结由 DSH 承担；插件提供职责明确的只读能力及必要使用说明。

### 1.2 非 Redis 写入的准确含义

| 操作 | 本方案范围 | 约束 |
| --- | --- | --- |
| 查询值、类型、TTL、长度和有界诊断数据 | 纳入 | Host 校验命令及参数，遵守权限和预算 |
| 切换 DB、建立或断开连接 | 纳入 | 仅当前会话，来自用户明确意图；不能因普通查询自行换环境 |
| 选 Key、选字段、刷新、切格式、展开面板 | 纳入 | 属于界面状态变化；需要有效目标和界面回执 |
| 保存环境标识、常用筛选、本地报告 | 纳入 | 属于本地文件或偏好变化；按用户明确请求保存，不包含凭据和未选择的数据 |
| 修改值、TTL、删除或重命名 Key、导入 Redis | 暂缓 | 不注册、不开放对应工具和按钮 |
| Stream ACK、claim、消费推进、消费组创建删除 | 暂缓 | 会改变消息或消费状态，不能算只读诊断 |
| 清慢日志、杀连接、改配置、故障切换、迁移、持久化管理 | 排除本轮 | 不因排障自动修复服务器 |
| 自由命令、Lua、Functions、任意脚本执行 | 排除本轮 | 不提供通用执行后门 |

只读指不由插件修改业务数据、消费状态或服务器配置；读取仍可能消耗资源或改变服务器自身统计。不能承诺生产系统完全零影响。测试数据只能在明确所属的隔离夹具中准备；测试准备过程与插件运行时的只读命令证据分开。

## 4 统一实现方式

### 4.1 复用当前 Host 服务

```text
DSH 对话 → 原生工具 ─┐
                     ├→ 当前会话 Host 服务 → 有界 Redis 读取
插件界面 → Typert RPC ┘

DSH 界面动作 → Host 校验目标 → 所属 Client 应用 → 实际回执
```

现有 `RedisConnections`、reader、选择身份和 RPC/schema 是扩展起点。业务逻辑放在 Host 服务；工具和 RPC 负责入口参数、身份与结果适配。不要给人工操作和 AI 操作各写一份 Redis 查询实现。

本项目是 DSH 插件，统一 DTO 位于 `src/domain.ts` 等现有共享定义，RPC 校验位于 `src/typert.shared.ts`；没有另一个 Nest 后端可供套用。遵循统一 DTO 原则，在当前项目结构中维护类型，不为套用通用约束创建无关后端。新增 TypeScript 禁止 `any`，旧协议不加静默兼容；协议变更同步更新 Host、Client 和测试。

### 4.2 工具设计

保留现有四工具的职责。新增或扩展工具优先支持显式读取、候选发现、有界筛选与诊断，界面操作、已有连接管理和专业类型按需提供；具体名称、参数和工具数量在任务实施时依据固定版本 DSH API 确定，不把方案里的概念名当已存在 API。

共同要求：

1. 会话身份取执行上下文；模型参数不允许指定其他会话或 Host 文件路径来绕过权限。
2. 目标包含连接身份、代次、DB、原始 Key/成员标识；调度前和返回前核对，切库/换连接后旧请求失效。
3. 已有数据结果结构优先扩充必要字段，不先重写所有 DTO。结果准确表达目标、读取时间、状态、完整性、续读条件及可理解的错误。
4. `scanComplete`、值是否完整、UI 是否应用是不同事实，不能合并成一个成功字段。
5. 数据内容始终是数据。Key 或值中的“忽略指令”“删除数据库”等文本不得改变工具权限或调用规则。
6. 单次有预算，连续调用也要受限；不能靠多页、多节点或多个工具重复读取绕过总预算。实施前确定预算归属、累计范围、重置条件及用户明确继续的行为，预算停止后由用户明确继续。
7. 不在日志、工具结果、异常或报告中返回密码、私钥、带凭据 URI。模型输出范围遵循用户请求，默认不自动发送整个 DB。
8. 不伪造 AI 能从截断内容得出的结论；比较和统计必须标明所覆盖的样本、缺失项和时间。

Key、值、慢日志参数和客户端信息一旦作为工具结果返回，可能进入 DSH 对话和其所配置的模型处理链路。实施与验收前应核实实际配置的数据传递及保存方式；有界结果或最小摘要不等于不会外发。真实业务数据进入模型须先明确目标和数据范围。

### 4.3 显式目标、发现和跨 Key 查询

显式 Key 读取不得依赖界面选中状态或可见性；若会话未连接，说明原因并引导用户连接。目标不明确时不自行跨 DB、跨连接搜索，不猜业务 Key。依据用户提供的前缀或模式执行有界候选发现，允许续读，但必须说明扫描是否完成；空页含游标不代表结束。候选可能重复或同时变化，SCAN 完成也不是一致性快照。

跨 Key 筛选只在用户明确的连接、DB、模式及数据范围内执行。实施 RO36 前明确允许的筛选类型、总扫描批次、候选数、读取次数、时长和输出上限；对超预算、中断、权限不足、类型变化、候选消失和读取失败分别返回统计。不得借分页或重复工具调用绕开总预算；预算耗尽后按既定规则等待用户明确继续。结果给出匹配数、实际检查数、失败/跳过数、覆盖和采样时间；只有全部必要读取成功且覆盖完整才可称相应范围查询完整，且仍说明并发变化影响。避免将所有原始值送入模型，按用户请求和实际权限只返回必要事实；真实业务数据进入模型前明确目标与范围。

### 4.4 界面动作可靠完成

优先使用目标 DSH 版本已有、已核验的侧栏和客户端能力；若无法程序化打开侧栏，返回“需要用户打开 Redis 面板”，不要私自改宿主或依靠任意 DOM 注入。

Host 发出动作不等于界面执行成功。动作至少需要请求标识、目标代次、有效期和终态；Client 回报已应用、未挂载、不支持、目标过期、超时或被用户新操作取代。字段名称在契约任务中确定。复用现有通道能够满足时，不新增消息总线或持久队列。

多个 Client 或窗口同时挂载同一会话时，明确当前接收者；无法唯一识别就拒绝自动应用，不能让多个窗口争相改变选择。用户的新选择优先；迟到动作不抢回焦点。首次仅实现单次手动刷新，不让 AI 自动开启持续轮询。

### 4.5 已有连接的 AI 管理

先做列出、按唯一资料 ID 请求连接、断开和切换；AI 返回连接摘要，不返回 CA 正文或凭据。相同名称不得猜选，资料在列出后变化时重新核对目标。

需要密码、私钥或 SSH 认证时，使用插件的本地输入界面；工具返回等待输入或需要用户操作，不能在未建立连接时报告成功。凭据不作为模型工具参数，不写入 DSH 对话。新建/修改连接地址与认证参数仍由人工表单管理；环境标签由用户填写，不从名称猜测“生产”或“测试”。

连接切换先校验用户意图和目标，再释放当前会话资源；不影响其他会话。失败不得悄悄改连另一个服务器。开启新连接与选择 DB 都是状态变化，不能隐藏在普通读取工具内。

## 5 各阶段实施范围

### 5.1 基础与直接查询：RO01–RO06、RO27 必要子集、RO34

复用现有宿主契约、会话身份、错误、分页和预算。RO34 以真实 DSH 及用户模型验收“无需打开面板或选中 Key，直接读取明确 Key、必要字段和可用元数据并解释”；针对无连接、Key 不存在、类型不符、权限不足和数据不完整分别给出结果。显式 Key 与选中项分支分开验证；旧验收不能替代当前构建验证。

扫描保留游标链和去重；空页有游标可继续，停止原因区分取消、预算、网络失败和自然完成。不得用 `KEYS *`、无限读取或无限重试补齐结果。旧 RO01–RO06 的历史完成状态和证据保留，但不因此声称新闭环已完成。

### 5.2 候选发现与筛选：RO35、RO36

依据用户明确线索查 Key 名，无法确定时列候选或请用户补充信息；不将 MATCH 当成语义搜索。RO36 在明确范围内对候选读取必要字段并筛选，执行和回答遵循第 4.3 节。先明确预算、续读和覆盖表达，再做实现及真实模型验收。

### 5.2.1 按需界面、筛选预设和连接：RO07–RO13

界面动作仅在用户请求打开、定位、刷新或使用当前选择时触发；普通读取不等待界面动作。保留已实现的动作回执和竞态保护，定位按原始身份进行，不以截断标签代替二进制身份。List 下标仅代表采样时位置；Stream 同名字段按实际字段位置区分。用户新操作优先，迟到回执不得覆盖新选择。

刷新、格式、筛选预设与连接管理依据实际用户需求安排；筛选预设只保存名称和条件，不保存结果值、游标或密码，属于用户明确要求的本地变更。RO13 分别验收自然语言定位、反向选中及必要的连接行为，不将格式、保存、断开串成所有查询的必经流程。

### 5.3 第 3 阶段暂缓

String/Hash 编辑、TTL 修改、删除、写入预览、人工确认令牌、并发冲突检测、写后回读全部保留在任务清单的暂缓区。不增加写入工具占位、不做解锁开关、不预埋通用执行器。以后由用户重新明确范围后再设计，当前只读阶段不依赖它们。

### 5.4 常见诊断：RO14–RO20 及 RO29 按需

先建立按功能区分的能力与权限结果，再分别扩展诊断 reader。能力未知、服务器不支持、ACL 拒绝和网络错误不得互相冒充。能力探测只读且有预算，不临时提高 Redis 权限。

| 诊断项 | 候选读取方向 | 边界 |
| --- | --- | --- |
| 服务器概况 | 明确 INFO 小节 | 显示版本、采样时间和缺失字段，不读 CONFIG 全部配置 |
| 慢日志 | 有数量上限的 SLOWLOG GET | 参数可能敏感；AI 默认取最小必要摘要，不允许 RESET |
| 客户端列表 | 受限 CLIENT LIST | 响应可能无法服务端分页；超限明确失败，不伪装只取前几条就零成本 |
| Key 信息 | 复用 TYPE、PTTL、长度，评估 MEMORY USAGE | 每项能力单独验证；无权限不等于占用为零 |
| 快照比较 | 比较同一目标的两次有界结果 | 时间不同不构成原子快照，业务并发变化需说明 |
| 本地报告 | 导出用户选定的已读结果 | 路径由受控保存界面决定，不写回 Redis、不自动上传 |

只提供快照和按需读取；不在本轮引入持续后台监控、MONITOR、Pub/Sub 长连接、自动告警或自动修复。权限不足就展示缺失信息，不调用终端、redis-cli 或其他插件绕过。

### 5.5 连接扩展：RO21–RO26 按需

先完成连接架构与固定版本依赖选择，根据实际环境决定 mTLS、SSH、Sentinel、Cluster 的顺序；各模式以公共契约为前置，彼此独立交付，不把“集群支持”作为一个无细节勾选项。

- **mTLS**：客户端证书、私钥和口令只在受控本地/Host 端使用，保持服务器身份验证，补证书错误和证书轮换行为。
- **SSH**：核对 SSH 服务端身份，绑定本地回环端口，明确隧道与会话的所有权；退出、取消、失败关闭本任务资源。不修改系统 SSH 配置或代理。
- **Sentinel**：明确 Sentinel 与数据节点各自认证、发现、角色和切换状态；主节点变化使旧代次及游标失效。不会触发手动 failover。
- **Cluster**：明确槽位、节点、MOVED/ASK 路由、重定向次数和节点预算。Key 扫描按主节点分别推进、去重并汇总覆盖范围；节点缺失或拓扑变化不能称全库完成。Redis Cluster 只支持 DB 0，不能继续展示可切换到其他 DB 的能力。

正式 transport 是项目自建实现。选择扩展它还是采用成熟客户端，需要先核验目标库版本、取消/超时语义、额外连接、重连行为、二进制保真和许可。只实现选定方案，不长期保留两条互相兜底的旧路径。SSH/mTLS 与 Sentinel/Cluster 的组合只有实际验证后才列为支持。

### 5.6 专业类型：RO27–RO32 按需

| 数据能力 | 首轮范围 | 明确不做 |
| --- | --- | --- |
| 六基础类型精确读取 | 完善范围、方向、成员定位与有界比较，必要时新增只读接口 | 其他基础类型编辑 |
| RedisJSON | 路径读取、类型与截断信息；先验证模块和服务器版本 | JSON.SET、删除、合并和数组修改 |
| Stream 消费组 | 组、消费者、待处理消息与 lag 的只读诊断 | XREADGROUP、XACK、XCLAIM、XAUTOCLAIM、XGROUP 修改操作 |
| TimeSeries | 指定时间范围读取；图形仅展示实际已读样本 | 新增样本、规则、压缩和补数据 |
| Bitmap/GEO | 有界位范围或指定成员坐标读取 | 写位、位置写入和存储查询结果 |

只读命令也须逐条核查副作用和响应上限。HyperLogLog、Bloom、向量/Search 等保留后续候选，不默认启用；尤其不能仅凭“查询”名称认定命令完全不改内部结构。专业类型无法有效限制响应或没有可核验文档时，该项明确阻塞，不能先实现无界拉取。

## 6 验收与交付

### 6.1 每项功能完成条件

1. 变更前说明原因、完整阅读涉及文件；复用既有设计，保持职责单一。
2. 有代码变更时先 `pnpm typecheck`，修复类型错误后执行适当专项；阶段出口执行项目 `pnpm check`，不跳过构建检查。
3. 新增命令与参数有官方契约和测试，非法命令、错误目标、超预算、取消和迟到结果被拒绝。
4. 有界面变化时保留真实原生 DSH 操作结果；合成浏览器、静态检查和真实模型验收分开记录。
5. AI 能力以用户问题为单位用真实 DSH 与用户模型验收：记录原问题、工具调用、目标、范围、答案与不足；明确 Key 场景不预选或打开面板，不依靠 Shell/redis-cli 绕过插件；脚本模型只能证明接线。
6. 每个小目标更新 `UPDATE_LOG.md`，记录文件、原因、影响和验证；每个完成并验证的节点分别本地 Git 提交，不自动推送。只把完成且有证据的任务标完成。

### 6.2 必须覆盖的场景

- 明确 Key 无面板选择、线索不足、多候选、无匹配、有界跨 Key 筛选、部分扫描或读取失败；未连接、错误 DB、Key 消失、类型变化、无权限、凭据缺失。
- 二进制 Key/字段、重复 Stream 字段、长整数、空页带游标、值截断、超大响应。
- 快速选行、切库、换连接、跨会话、多个界面、面板关闭、取消、超时、工具结束后的迟到结果。
- DSH 读到恶意指令样式的数据时，权限和只读边界不变。
- 用户要求写入时，当前版本明确不支持，不注册写工具、不转用任意命令执行。
- 诊断权限不足、部分节点不可达、模块不存在；结果准确描述覆盖范围。
- 插件禁用、重载、卸载后，所属连接、游标、界面动作和隧道清理；不清理其他会话或用户服务。

### 6.3 证据与环境

复用 [tests](../tests/)、[scripts](../scripts/) 中适用的夹具，先核对脚本前置和固定路径，不能直接运行历史脚本覆盖旧报告。新增验收报告放 `docs/verification/`，标明源码提交、包哈希、宿主、Redis/模块版本、模型、实际工具调用、结果和未覆盖环境。历史 205 项测试不是下一版的固定目标数量。

不额外启动 `npm run dev` / `npm run start:dev`。日常 DSH、Redis 和代理配置不动；确需隔离服务时先核验端口、路径和所有权，结束只停止本任务启动的服务。真实业务 Redis 的连接和数据进入模型需要另有明确使用范围，本次文档授权不包含它们。

本地打包和隔离安装验收完成后才能声明相应范围的候选可用；最终模型验收应核实并使用用户实际的 DSH 环境，隔离数据不等于隔离宿主可替代日常实例；不自动更新日常 profile，不推送、不移动 tag、不创建 Release、不发布 npm。新版本号与发布范围留到实际交付时确定。
