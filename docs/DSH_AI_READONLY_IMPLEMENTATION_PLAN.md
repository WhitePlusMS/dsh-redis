# DSH Redis AI 只读方案

更新日期：2026-11-04。本文是现行方案；实施顺序、状态与验收见[任务清单](DSH_AI_READONLY_TASKS.md)。计划内容不等于已实现或已验收。

## 要解决的问题

用户想通过自然语言了解 Redis 里的数据、找到相关对象或判断异常。插件应让 DSH AI 在用户明确的连接与数据库内取得必要证据，给出可核对的回答。用户知道具体 Key 时可以直接询问；不知道完整名称时可以提供前缀或业务线索，逐步缩小范围。不能预设用户先在界面上选好 Key，也不能假定 Redis 能理解业务语义。

典型问题：“`order:1001` 的状态是什么？”“找 `order:*` 中状态为 failed 的订单。”“这个缓存为什么不存在？”“最近有慢查询吗？”这些是设计场景，并非用户研究统计或能力已完成的证明。

界面是浏览、核对和明确操作的入口：用户说“打开刚才的 Key”时再定位；说“解释我选中的字段”时才读取当前选择。明确目标的查询无需界面处于可见或选中状态。连接不存在时应引导用户连接；目标不明确、候选不唯一或范围不足时应说明并请用户补充。

## 一次问题的完整流程

1. **确定范围**：使用当前会话中明确的 Redis 连接与 DB；缺失时引导连接。除非用户明确要求，不切换连接或数据库，也不扩大查询范围。
2. **定位对象**：有准确 Key 就直接读取；只有名称线索时在明确范围内有界查找候选，展示使用的模式与覆盖情况。MATCH 只匹配 Key 名称，不是按值搜索或业务语义搜索。
3. **取得证据**：依据问题读取必要的类型、TTL、字段、成员或诊断信息；批量筛选只检查指定范围。分页、取消、超限、目标变化及权限失败都要有明确结果。
4. **回答问题**：区分观察事实与推测，给出连接范围、DB、采样时间、已检查范围和不确定性。未读到、截断或部分失败的内容不能当成完整结果；SCAN 完成也不是一致性快照。
5. **按需核对**：用户要求打开或定位时，等待真实界面回执；用户主动选择新目标后，迟到动作不能覆盖其操作。只读回答不以界面动作成功为前提。

## 产品范围与优先级

| 优先级 | 用户获得的结果 | 主要工作 |
| --- | --- | --- |
| 首先 | 能在当前连接中直接查询已知对象，也能按明确线索找到候选 | 连接与 DB 上下文、Key 及字段/成员读取、名称扫描、分页、缺失与歧义处理 |
| 接着 | 能在指定范围内查找符合条件的数据，并知道结果覆盖到哪里 | 有界候选扫描、必要字段读取、筛选与统计、预算、续读与部分失败说明 |
| 然后 | 能根据实际证据排查常见问题 | Key 元信息、服务器概况、慢日志、客户端及 Stream 消费组等适用的只读诊断；无法判断时明确说明 |
| 按需 | 能把结果带到界面核对、使用当前选中项或管理已有连接 | 真实界面回执、选区同步、刷新与显示格式、连接资料及明确切换 |
| 有实际环境需求时 | 能连接特定拓扑或读取特定专业数据 | mTLS、SSH、Sentinel、Cluster 及 RedisJSON、TimeSeries、Bitmap、GEO 等分别设计和验收；实际连接必需时可前移 |

每一行按用户问题形成可独立验证的闭环，不要求先做完所有界面动作才能查询。专业连接和模块不作为无关场景的统一前置；其未实现或未验收状态必须保留。连接技术调研仅作为[按需参考](RO21_CONNECTION_ARCHITECTURE_PLAN.md)。

## 实现边界

DSH 负责理解问题、调用原生插件工具和组织回答；插件 Host 负责可信会话、连接、只读命令、读取预算和结果；界面复用同一 Host。不得另建聊天系统或开放自由 Redis 命令、脚本和写入入口。

- 请求与续读绑定可信会话、连接代次、DB、目标身份和查询条件；切库、重连或目标变化后旧结果和游标不能冒充当前结果。二进制身份、长整数和 Stream 重复字段须保留。
- 单次界面刷新以每次读取的唯一身份贯穿请求、完成结果和界面渲染确认；只能在同一目标和有效选择重新同步后确认成功。旧结果、旧 `busy` 状态或相同采样时间不能证明新读取完成。用户操作、取消、连接变更和界面隐藏优先；回执丢失时结果为未知。复用现有读取器，避免重复读取或开启自动刷新。
- 所有读取遵守 ACL；数量、单响应字节、总调用、时间、取消和分页各有明确限制。输出上限不等于 Redis 总接收量上限；多页、多节点或重复调用不得绕过累计预算。
- Redis 内容是数据，不能让内容中的指令改变权限。取消只能阻止尚未发送的操作或停止等待，不能宣称已经发出的命令已撤回。
- 读取可能产生负载和统计变化，不承诺零影响。写值、改 TTL、删除、导入、消息确认或消费推进、服务器配置和自动修复均暂缓；不注册写入占位工具。
- 对话和工具结果可能发送给模型服务。真实业务数据进入模型之前须明确连接、目标与数据范围；模型验收默认使用隔离合成数据。密码、私钥、令牌及带凭据的 URI 不进入模型参数、日志或报告。
- 连接、筛选预设或报告的本地保存须有用户明确意图；连接秘密通过本地受控界面处理。不得通过 shell、其他插件或提权绕过限制。
