**Document version:** v2
**Last updated:** 2026-10-20
**依据：**当前双语 README、安装与开发说明，以及项目内已有的六类型隔离验收和真实 Hash 对话验收。目标读者与定位属于根据项目范围整理的工作假设，没有用户访谈、市场规模或付费验证。

## Product Overview

**One-liner：**在 DSH 侧栏查看 Redis，并让当前对话按需读取选中的内容。

**What it does：**DSH Redis 是 DeepSeek Harness（DSH）的社区只读插件。用户手动连接单机 Redis 后，可以浏览 DB 和 Key，查看 String、Hash、List、Set、ZSet、Stream，并在同一个 DSH 对话里检索 Key、读取当前选择。集合选行后直接显示详情，保留当前工作区。

**Product category：**DSH 开发工具插件、Redis 数据查看器。

**Product type：**个人开发工具；由 DSH Host 连接 Redis，Client 提供原生右侧栏，通过原生 Tool API 提供对话读取，不是 MCP server。

**Business model：**当前采用 MIT 许可、本地开发交付；没有已确认的商业定价、公开发布地址或注册表下载入口。

## Target Audience

**Primary audience：**已经使用 DSH Web 进行开发、调试，需要查看单机 Redis 的个人开发者。

**Secondary audience：**维护使用 Redis 的应用、需要检查字段和数据结构的技术人员；能理解连接权限和模型数据去向的插件试用者、维护者。

**Target companies：**不限定行业或公司规模；当前证据不足以建立企业采购画像。

**Primary use case：**在 DSH 工作区内定位 Key、检查字段，再围绕当前选中的内容提问。

**Jobs to be done：**

- 通过 DB、Key 目录与筛选定位要检查的数据。
- 在表格与同屏预览中检查字段、成员、下标或消息，不反复切换详情页面。
- 让同一 DSH 对话按需读取已连接的目标，减少重新描述 Key 和手工复制内容的步骤。

**Use cases：**查看 Hash 配置或状态字段、检查 List/Set/ZSet 的元素、查看 Stream 消息字段、用 Text/JSON/Hex/Base64 检查当前已读内容。它们是能力对应的适用场景，不是新增客户案例。

## Personas

当前是个人工具，没有多角色采购模型。主要使用者同时决定是否安装、选择 Redis 连接、判断是否把读取结果发送给所配置的模型。团队共享连接、成员权限与集中审计不属于当前产品。

## Problems & Pain Points

**Core problem：**Redis 查看与 DSH 对话分开时，定位数据和向模型说明当前对象需要额外切换或复制。

**Current workflow：**独立 Redis GUI、Redis CLI、复制数据到对话均可完成相应任务。本项目把常用查看和按需读取放进同一个 DSH 工作区，不据此判断其他工具不足。

**Cost：**可以减少工作流中的切换与重复输入；没有可引用的耗时、效率提升比例或性能对比。

**Emotional tension：**未开展相关访谈，不推测用户焦虑或满意程度。

## Competitive Landscape

| 替代方式 | 适用情况 | 本项目选择的侧重点 |
| --- | --- | --- |
| 独立 Redis GUI | 专门管理和浏览 Redis | 在 DSH 原生侧栏查看，并复用当前对话连接 |
| Redis CLI | 明确知道命令和目标的终端操作 | 通过目录、表格、选行和格式化预览查看 |
| 手工复制到对话 | 临时解释一段已提取内容 | 工具调用时按当前选择读取，保留会话和 DB 身份 |
| 通用数据库插件 | 多种数据库的集中访问 | 当前只聚焦 Redis 六类型的日常只读查看 |

这些是工作方式的中性比较，没有逐一验证其他产品的新版本，也不声称功能独占或全面替代。

## Differentiation

**核心卖点：**

1. **查看与提问在同一个 DSH 工作区。**原生右侧栏浏览，四个原生工具复用本会话手动建立的连接。
2. **选行直接查看。**Hash、List、Set、ZSet、Stream 在同一视图展示选中内容；Stream 同名字段保留独立身份。
3. **日常查看范围明确。**六类型、分批加载、筛选、格式化、查找、复制与可选自动刷新；当前不提供 Redis 数据写入。

**Mechanism：**Host 用同一会话连接读取 Redis，UI 和 AI 分页状态分开；Client 只同步选择标识，工具实际调用时重读值。未连接的对话不借用其他对话连接。

**Why this matters：**用户可以在当前工作区定位数据，并让对话围绕所选对象继续分析。该表述描述流程，不承诺模型回答准确率或任意排障结果。

## Objections

| 疑问 | 准确回应 |
| --- | --- |
| 能修改或删除数据吗？ | 当前只读；写入与逐次人工确认只在后续候选中 |
| 能连接所有 Redis 环境吗？ | 当前单机直连与 TLS；无 Cluster、Sentinel、内置 SSH 隧道；实际验证载体是 Windows + DSH Web 0.2.0-rc.2 |
| 密码和数据去哪里？ | 连接资料不保存密码；对话工具输出进入 DSH 历史，并可能发送给该对话配置的模型服务 |
| 能直接打开客户快照吗？ | 不直接打开 RDB/AOF，也没有快照导入功能；连接的是正在运行的 Redis |

**Anti-persona：**需要数据写入、批量删除、清库、自由命令、集群管理、文件快照导入或企业共享治理的人，当前不能用本插件满足这些需求。

## Switching Dynamics

**Push（假设）：**希望减少查看数据后手工复制到 DSH 的步骤。

**Pull：**侧栏查看、当前选择识别、同会话连接与原生对话工具。

**Habit：**既有 GUI 和 CLI 已能完成常用工作，保持使用它们也是合理选择。

**Anxiety：**安装基线、只读范围与模型数据去向需要明确说明；不以笼统安全承诺代替这些事实。

## Customer Language

以下来自本项目发起者在开发对话中的要求，不作为外部客户证言：

- “在 DSH 侧边栏里可以查看 Redis 里的各种数据。”
- “选中一行就直接显示详情，别再来回跳页。”
- “我的 DSH 的对话可以直接访问看到 Redis 里面的内容才对的。”

**Words to use：**原生侧栏、同一对话、当前选择、六种基础类型、只读查看、分批加载、选行详情。

**Words to avoid：**全能管理、全面替代、零风险、所有版本兼容、完全本地、已上架、秒级处理、效率翻倍、自动修复、AI 读写。

| 术语 | 本项目中的含义 |
| --- | --- |
| DSH | DeepSeek Harness，承载插件和对话的宿主 |
| 连接资料 | 当前 profile 内保存的不含密码的连接设置 |
| 当前选择 | 侧栏选中的 Key、字段、成员、下标或 Stream 字段身份 |
| 对话工具 | 本插件通过 DSH Tool API 注册的4个工具；不是 MCP |
| 加载完成 | 当前有界查询的扫描状态，不代表一致性快照或全部值完整 |

**Style：**遵循 oil-tone，用完整自然句介绍功能；不编造作者经历、用户反馈、情绪和效果数字。

**Personality：**直接、克制、重视证据、面向实际操作。

**Visual direction：**README 保留现有真实界面截图、青紫橘导航与简洁层级。推广封面从同一隔离截图提炼 Hash 表格、选中行和预览，外层配色使用从界面青紫色调柔化的雾蓝与淡紫。生成封面和原生截图分别标明用途。

## Goals

**当前目标：**让首次接触项目的人理解用途、知道适用环境，并能根据安装指南完成一次手动连接和只读查看。

**Conversion action：**在匹配版本的 DSH Web 内安装已核对的本地包，查看一个 Key，再在同一对话询问当前选择。未确认公开仓库与下载地址前，不写“立即下载”“点星”或虚构 Issues 入口。

**Current metrics：**未收集安装量、活跃用户、转化率或市场反馈。维护者已于2026-10-20确认按个人开发者、六类型只读查看/同屏详情/同会话读取的定位继续；这不是市场验证，产品事实仍以已核对实现为准。
