## 范围和拆分原则

- 个人使用、严格只读、单机直连/TLS、配置在 profile 内共用而浏览状态按会话分离。
- P0 覆盖 String、Hash、List、Set、ZSet、Stream、RedisJSON、Bitmap、GEO、HyperLogLog、TimeSeries、Bloom 的查看能力。
- 基础显示是 Text、JSON、Hex、Binary/Base64 与显式 Base64 解码；压缩/其他序列化格式留在后续候选。
- 每票交付一条可展示或验证的用户流程，包含所需严格契约、Host 行为、UI 和有意义的验证；不按“写 DTO / 写后端 / 写前端”水平拆开。
- 字节身份、只读 Host、目标代次、错误和预算从第一条相关功能落地，并由之后类型票沿用；不推迟到最后补基础。
- 保持独立项目，不为更新参考源码进行无关重构，不修改 Git Graph 或 Database 原项目。包、侧栏、RPC 和样式使用独立身份。
- 任务正文不锁定具体代码文件路径或代码片段；实现位置由当前模块边界确定。
- 编号是依赖顺序，不是必须全串行。P0 优先调度，P1 的技术依赖不人为增加“全部 P0 完成”边。

## 共同验收约束

每张涉及 Redis 数据的票都必须验证只读命令、二进制身份、旧结果隔离、权限/消失/类型变化、取消/超时和实际结果边界；不能仅增加界面或只通过模拟就算完成。每张代码票执行适当的严格类型检查和专项验证，并记录真实结果与未验证范围。更新说明记录改动原因、影响和验证。

输出截断不等于驱动接收内存受限；扫描条数提示不等于固定结果大小。TLS 验证、HLL 缓存、TimeSeries 边界和 Bloom 概率语义按实施方案处理。测试只能使用独占测试数据；本次没有执行这些测试。
